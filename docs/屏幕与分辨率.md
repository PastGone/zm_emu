# 屏幕尺寸与分辨率

本篇记录两件事：
1. `.app` 头部里那四个"屏幕字段"的真实语义；
2. 模拟器怎么选屏幕尺寸（预设、`ZM_SCREEN`、两级夹紧），以及**为什么必须夹**。

---

## 一、`.app` 头部 0x174 ~ 0x183 是"支持区间"，不是"屏幕尺寸"

```
0x174  MinScreenWidth    支持的最小屏幕宽度
0x178  MinScreenHeight   支持的最小屏幕高度
0x17C  MaxScreenWidth    支持的最大屏幕宽度
0x180  MaxScreenHeight   支持的最大屏幕高度
```

结构体定义见 `src/tool/paser_info.h` 的 `AppletHeader`（含 14 条 `_Static_assert` 钉死偏移）。
Go 侧有两份同构实现，改字段时需同步：`go_tools/applet_header_tool/applet_header.go`、
`go_tools/applet_scan/app_header.go`。

**163 个样本的分布**（`go_tools/applet_scan` 扫出来）：

| 区间 | 个数 | 说明 |
|---|---|---|
| 240x320 ~ 240x320 | 47 | 固定尺寸型（如 000007ca 计算器） |
| 176x220 ~ 800x800 | 17 | 自适应型 |
| 128x160 ~ 800x800 | 14 | 自适应型 |
| 128x128 ~ 800x800 | 10 | 自适应型 |
| 176x220 ~ 320x480 | 9 | 自适应型 |
| 240x400 ~ 240x400 | 8 | 固定尺寸型 |
| 240x320 ~ 800x800 | 7 | 自适应型 |
| 320x480 ~ 320x480 | 4 | 固定尺寸型 |
| 128x160 ~ 900x900 | 3 | 自适应型 |
| 其余 | … | — |

> 早期实现把 `0x17C/0x180`（=**最大**）直接当成主屏尺寸，于是自适应型 applet 全都
> 跑在 800x800 / 900x900 上，画面按 800 宽摆 UI（菜单横向平铺），并触发下面第三节
> 那个越界写崩溃。

## 二、模拟器怎么选尺寸

实现在 `src/main.c`（`main()` 里解析完头部后的那个块），结果写入 `g_layer_w/g_layer_h`，
它同时决定：层缓冲尺寸、SDL 窗口尺寸、软件帧缓冲尺寸、`IShell::GetDeviceInfo` 上报的宽高。
三者必须一致，改分辨率只改这一处。

### 规则（按优先级）

1. **默认 240x320**（经典功能机），即 `k_screen_presets[]` 的默认档；
2. **可覆盖**，两种写法（命令行与同名环境变量等价）：
   - 直接写宽x高：`--screen 320x480` / `ZM_SCREEN=320x480`
   - 预设序号：`--screen 7` / `ZM_SCREEN=7`（序号同下表的左列）
3. **夹进该 applet 声明的 `[min,max]` 区间**：越界取最近的边界值，并打 `WARN`
   （即"可以自由调，但不小于它要的最小、不大于它要的最大"）；
4. **夹进模拟器容量上限** `LAYER_MAX_W/H`（当前 1024，静态数组按上限预留）。

> 优先级：**命令行 > 环境变量 > 内置默认**。实现见 `src/main.c` 的 `zm_parse_args()`——
> argv 解析出来的值直接 `setenv` 成同名 `ZM_*`，后面各模块照旧 `getenv`，
> 所以"命令行覆盖环境变量"是免费的（详见第五节）。

### 常用分辨率预设表

开机日志会整表打印一次，照抄名字或序号即可：

| 序号 | 名字 | 序号 | 名字 |
|---|---|---|---|
| 0 | 128x128 | 6 | 320x240 |
| 1 | 128x160 | 7 | 320x480 |
| 2 | 176x220 | 8 | 480x640 |
| 3 | 208x208 | 9 | 480x800 |
| 4 | **240x320（默认）** | 10 | 640x960 |
| 5 | 240x400 | | |

加档位就在 `src/main.c` 的 `k_presets[]` 里加一行；**序号会顺延，脚本里建议用名字**。

### 日志长这样

```
分辨率预设: 0=128x128 1=128x160 2=176x220 3=208x208 4=240x320 5=240x400 ...
屏幕尺寸: 240x320（默认；该 applet 支持区间 176x220 ~ 800x800）
```

被夹紧时：

```
WARN 屏高 960 超出该 applet 支持区间 220~800，夹到 800
屏幕尺寸: 640x800（ZM_SCREEN=宽x高；该 applet 支持区间 176x220 ~ 800x800）
```

## 三、案例复盘：00000462 三国情仇 —— 屏宽导致的越界写崩溃

**现象**：点主菜单"开始游戏"必崩，`err=8 (UC_ERR_FETCH_UNMAPPED)`，
PC 每次都不一样（`0x2C0000D0` / `0xCFA40000` …）——典型的"函数指针是垃圾值"。

**崩溃点**（applet 代码 `0x42C0`）：

```arm
ldr   r0, [r5, #0xCC]      ; 取子对象指针
cmp   r0, #0
ldrne r1, [r0, #0x24]      ; 取它的虚方法
blxne r1                   ; ← 跳野地址
```

**根因**：那个子对象指针被"菜单滚动动画"踩掉了。

对象布局（`obj = 0x1DAC50`）：

| 偏移 | 用途 |
|---|---|
| `+0x58 / +0x5A` | 屏幕宽/高（从 `GetDeviceInfo` 拿） |
| `+0xBC` 起、每项 4 字节 | **菜单项坐标数组**（x@+0, y@+2），容量只有 **4 项**（`+0xBC ~ +0xC8`） |
| `+0xCC` | **子对象指针**（init 时 `0x43DC` 写入） |

菜单是**横向循环传送带**：项间距写死 240，每帧所有 x 减 1（`0x40E0: sub r0,r0,#1` /
`0x40E4: strh r0,[fp,#0xBC]`），滑出左边的项由 `item[i] = item[i+1]` 轮转到队尾。

**每帧滚动几个槽位 `r7` 是按屏宽算的**，公式 `r7 = 屏宽/240 + 2`（整数除），实测 4 档全部吻合：

| 屏宽 | r7 | 写到的最高槽位 | 结果 |
|---|---|---|---|
| 240 | 3 | `+0xC4` | 安全 |
| 480 | 4 | `+0xC8` | 安全（刚好装满） |
| 720 | 5 | **`+0xCC`** | 踩指针 → 崩 |
| 800 | 5 | **`+0xCC`** | 踩指针 → 崩 |

实测写回记录（`ZM_MW=0x1DAD0C,0x1DAD20`）：

```
[MW] 写 0x1dad1c (+4) = 0x1dad30  PC=0x43DC   ← init：正常存入指针
[MW] 写 0x1dad1c (+2) = 0xad2f    PC=0x40E4   ← 动画把指针当 x 坐标减了 1
[MW] 写 0x1dad1c (+2) = 0xad2e    PC=0x40E4   ← 再减 1
→ R0=0x1DAD2E → blx 野地址 → err=8
```

**结论**：这是 applet 自己的 bug（它的数组只留了 4 个滚动槽位，没料到屏宽会到 720+），
容量和 `r7` 的算法都编死在它的机器码里，模拟器这边没有"数组"可改大。
唯一能在模拟器侧做的，就是**别上报现实中不存在的超宽屏幕**。

**注意**：夹紧用的是 *applet 自己声明的区间*，对 00000462 而言 720x320 仍是"合法"的
（在 176~800 内），但会崩。它实测的安全上限是 **480 宽**（`r7 = 480/240+2 = 4`，正好等于数组容量）。
这个上限是从它的代码里反推出来的，头部没声明，所以没有硬编进夹紧逻辑。

## 四、排查这类问题的常用开关

> 带"命令行"一列的项也可以写成环境变量（同名 `ZM_*`）；
> 其余只提供环境变量形式。`zm_emu --help` 会打印这张表。

| 命令行 | 环境变量 | 用途 |
|---|---|---|
| `zm_emu <app.app>` | `ZM_APPLET` | 跑哪个 applet（短名或完整路径） |
| `--screen WxH\|序号` | `ZM_SCREEN` | 指定屏幕尺寸（本机复现/对比） |
| `--log LEVEL` | `ZM_LOG` | 日志级别 off/error/warn/info/debug |
| `--click "x,y;…"` | `ZM_CLICK` | 无头自动按序点击 |
| `--mw lo,hi` | `ZM_MW` | 监视内存写入 |
| `--pc lo[,hi]` / `--pc2` | `ZM_PC` / `ZM_PC2` | PC 观察点 |
| `--trace` | `ZM_SHOW_TRACE=1` | 自定义 trap 追踪 |
| `--disasm` | `ZM_DISASM=1` | 反汇编日志 |
| `--screenshot 前缀` / `--shot-every` / `--shot-max` | `ZM_SCREENSHOT` / `ZM_SHOT_EVERY` / `ZM_SHOT_MAX` | 帧缓冲存 PNG |
| `--list-screens` | — | 列分辨率预设后退出 |
| `-h` / `--help` | — | 帮助 |

只提供环境变量形式的（较常用的几个）：

| 开关 | 用途 |
|---|---|
| `ZM_MW_MAX=N` | `--mw` 的条数上限（默认 300） |
| `ZM_STAT=1` | 统计各槽位调用次数与点击坐标，退出时打印 Top 榜 |
| `ZM_STEP=1` | 每个 trap 后等回车（单步） |
| `ZM_ULIBC_HEAP=0` | 堆退回 bump 分配器（排查 UAF/double-free 用，free 变空操作） |
| `ZM_FONT` / `ZM_FONT_SIZE` | 换渲染字体 / 字号 |
| `ZM_DUMP_BUTTONS` / `ZM_DUMP_LAYER` | dump 按钮矩形 / 存每层缓冲图 |
| `ZM_LOG_UCS2` / `ZM_LOG_OPEN` / `ZM_TRACE` | 更细的日志开关 |

典型定位流程（本次就是这么走通的）：
`--click` 脚本化复现 → `--pc` 拿到崩溃时的 LR（=调用点）→ 反汇编调用点找到间接调用
→ `--mw` 监视被调用的那个指针字段 → 抓到"谁把它改坏了" →
对比不同 `--screen` 下的行为，确认与分辨率相关。

## 五、为什么调试开关用环境变量、而入口参数用命令行

`src/main.c` 顶部的 `zm_parse_args()` + `zm_set_env()`：argv 解析出来的值直接
`setenv` 成同名 `ZM_*`，后面 12 个模块照旧 `getenv`，于是
**"命令行 > 环境变量 > 内置默认"** 是免费的，那些模块一行都不用改。

分工的理由：

- **命令行**负责一等公民参数（跑哪个 applet、屏幕尺寸、日志级别）与 `--help`：
  可发现（`--help` 列全）、当次进程有效（不会像 `export ZM_SCREEN=…` 那样
  污染后续所有运行，忘了极难查）、给非法值能立刻报错退出。
- **环境变量**继续承载那 46 个调试/诊断开关：它们散在各模块深处、多半是
  "用的时候才 `getenv`"，全改成命令行要么加全局 config 结构体、要么逐层透传，
  对临时开关不划算；组合调试时 `ZM_MW=… ZM_PC=… ./zm_emu` 也最省事
  （与 `SDL_VIDEODRIVER`、`ASAN_OPTIONS`、`RUST_BACKTRACE` 同款惯例，`test_all.sh` 就在用）。

跨平台注意：

- Windows 下环境变量语法不同（`set` / `$env:`），且命令行里没有 `setenv`，
  已用 `_putenv_s` 兜住（`zm_set_env()`）。
- **WASM/Emscripten 是唯一需要留意的点**：`getenv` 只认构建期/JS 侧注入的
  `Module.ENV`，没有 `VAR=x ./prog` 这种用法；命令行参数在 node/worker 下反而自然。
  远期真要上 WASM 时，调试开关这套得改成 `Module.ENV` 注入或改成命令行。
- glibc 在严格 `-std=c23` 下默认隐藏 POSIX 符号，`setenv` 需要
  `_POSIX_C_SOURCE=200809L`——已写在 `main.c` **最顶部**（特性宏必须在任何系统头之前）。
