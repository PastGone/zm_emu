# Web 模拟器项目与 Applet 运作原理文档详细总结

这份音频讲解基于 unicorn 内核的 模拟器整体运行逻辑，核心分为两层架构关系、完整初始化启动流程、回调与陷阱中断执行机制三大部分，完整梳理如下：

## 一、整体分层架构：外部模拟器 + Applet 沙箱

1. 职责划分
Applet：承载业务核心逻辑、程序指令执行；
外层模拟器：提供完整运行环境、硬件模拟、外部资源接口。
1. 跨层交互机制
Applet 运行时需要内存、IO、图形等外部资源，会向固定预留内存地址发起请求；
项目提前固化所有交互地址，通过虚表统一管理，Applet 跳转至指定地址即可触发外部模拟器处理对应请求。
1. 对比真实物理设备：真机是动态地址访问外设，本模拟器主动把交互地址固定、预填表格，实现标准化跨层调用。

## 二、main 主文件完整初始化全流程（线性执行步骤）

主程序负责全部环境搭建，顺序执行 7 步初始化：

1. 打开并解析 Applet 头部
读取 Applet 文件头，提取运行参数、环境配置，为后续分配资源做准备。
2. 初始化核心模拟内核 unicorn
启动 Qemu 精简版指令模拟引擎，作为整个模拟器底层执行核心。
3. 全局内存映射（核心大步骤）
划分模拟器完整内存空间，划定独立功能分区：功能区、堆内存、码表存储区、外部调用专用地址区；统一分配所有交互地址的内存位置。
4. 构建全局虚表（内存映射子步骤）
先申请虚表内存空间，再向表格内填充各类外部接口、跳转地址映射关系，作为 Applet 访问外部的索引表。
5. 注册钩子 Hook 拦截器
绑定所有预留外部访问地址；当 Applet 跳转到指定地址时，钩子捕获跳转指令，将执行权转交外层模拟器处理。
6. 载入待模拟程序
把 Applet 业务程序加载到之前划分好的对应内存区域。
7. 启动模拟运行
配置 CPU 寄存器、挂载各类初始化回调函数，正式进入模拟执行阶段。

## 三、模拟运行阶段：回调、陷阱中断与事件循环流程

1.寄存器与回调预置
启动前预先配置 CPU 寄存器，同时注册全局初始化回调，作为 Applet 启动后的首个外部处理入口。

1. applet 初始化完成触发陷阱中断
模拟器执行初始化流程（IPLC）时，自动跳转至预设回调地址；该地址存放于陷阱区 / 陷阱表，模拟器内核可捕获此次跳转，触发陷入中断。
1. 执行外部初始化回调函数
捕获中断后运行回调逻辑，由外层模拟器完成所有 Applet 依赖的底层环境初始化操作。
1. 进入持续事件循环

## 四、整套交互机制的设计优势补充

1. **固定地址+虚表方案对比真机**
真实硬件设备访问外设使用动态地址，寻址逻辑复杂；本项目预先固化全部外部调用地址，统一录入虚表做映射管理。Applet无需适配多套寻址逻辑，仅跳转固定地址即可发起系统调用，降低Applet程序开发适配成本，同时方便模拟器统一拦截、转发所有外部请求。
2. **钩子Hook + 陷阱Trap双层拦截体系分工**

- Hook钩子：提前绑定所有外部访问地址，负责第一时间捕获Applet的跨层跳转行为；
- Trap陷阱表：统一存放回调入口地址，跳转至该区域地址会触发内核中断，把执行权强制交给外层模拟器处理。
二者配合实现隔离：Applet仅专注业务逻辑，所有底层操作全部剥离至模拟器层，沙箱隔离性更强，也方便后续编译为WASM部署到网页端。

## 五、全流程闭环总结

1. 前置准备阶段：main程序解析Applet头部参数，初始化unicorn模拟内核；
2. 环境搭建阶段：划分内存分区、填充虚表映射、注册拦截钩子，完成完整内存环境构建；
3. 程序载入与启动配置：加载Applet程序至对应内存，配置CPU寄存器、挂载初始化回调；
4. 中断回调处理：applet初始化完成跳转陷阱地址，内核捕获中断，执行模拟器侧环境初始化；
5. 长期运行阶段：底层环境就绪后进入事件循环，持续处理Applet的各类外部调用、用户交互事件，模拟器持续提供内存、图形、音频、文件等底层能力支撑。

## 六、和前文文档（工具链、目录结构）关联补充

这套运行流程依托前文介绍的整套工具链落地：XMake负责编译构建、SDL提供图形渲染底层库、unicorn作为指令模拟核心、Go编写配套辅助工具；代码分层上依靠`emul.c`完成内存与虚表构建、`trap.c`统一转发外部调用、`event.c`处理循环事件，目录下ADO/FS/GFX等文件夹分别承载音频、文件、图形对应的外部接口函数，形成从编译工具、底层模拟内核、源码分层架构到完整运行流程的完整体系。
