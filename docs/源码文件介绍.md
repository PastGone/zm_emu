# 文档详细总结

这份音频介绍模拟器项目中**Applet内部与外部的调用关系**，分为两大板块：Applet依赖外部提供的能力、项目源码目录与核心文件分工。

## 一、Applet与外部的能力划分及对应代码目录

1. **能力分工逻辑**
Applet自身仅具备基础业务逻辑，无底层操作能力，内存申请、音频播放、文件访问、字符串处理、画面渲染等所有底层操作，全部依靠外层模拟器提供接口实现。
2. **src/zmaee各功能目录用途（存放外部对接函数）**

- audio：音频相关外部对接函数，处理音乐播放等音频操作；
- FS：文件系统对接函数，负责文件访问相关能力；
- GFX：图形渲染相关外部函数；
- inc：存储解析出的返回值、各类事件代码；东西是由逆向力来的但是这个**按键码具体没有实现**
- Runtime：存放系统层面相关操作函数。

## 二、SRC根目录下核心源码文件职责

1. `emul.c`：项目最核心文件
定义全部内存地址、全局变量；承载内存映射、虚表构建、Applet程序载入、钩子注册、Applet启动全流程关键逻辑。
2. `event.c`：专门负责各类事件的处理逻辑。
3. `hook.c`：实现钩子相关代码，仅包含3个基础钩子函数，重要程度较低。
4. `main.c`：把控程序整体运行主流程。
5. `trap.c`：调用转发核心模块
Applet内部发起的外部请求会统一进入该文件的总转发函数，再分发路由至对应功能接口完成处理，是内外交互的中转枢纽。

## 三、整体交互逻辑小结

Applet仅保留业务逻辑，底层全部能力交由外部模拟器实现；代码通过目录区分音频、文件、渲染、系统等功能接口，依靠`trap.c`做调用转发，`emul.c`承载模拟器初始化、内存、虚表、钩子、程序加载等底层核心流程，搭配事件、钩子、主流程配套文件完成整套内外调用体系。
